How to configure a MeshCentral client to replace Xwayland with Xorg

Intro

After deploying the MeshCentral agents to my VMs, I noticed that some of them produced an error screen complaining about Xwayland. This was as simple as modifying a config file and restarting a service.

INFO
Update (2026-11-19): The latest MeshAgent builds added Wayland support↗ (opens in a new tab), so a recent agent may connect without any changes. This guide still applies if you’d rather run Xorg, or if you’re on an older OS or agent.

How to Fix “This platform is configured to use Xwayland”

The error looks like this:

This platform is configured to use Xwayland, please modify config to use Xorg.

I got it on VMs running a desktop with the default Wayland session. Older MeshCentral agents capture the screen only through X11, and Wayland doesn’t give them that access, so the remote desktop shows this message instead. The fix is to make GDM use Xorg.

Why Xorg instead of Wayland

Most distros default to Wayland now. By design, it doesn’t let one app capture the whole screen the way X11 does, which is what an X11-only agent needs. Xwayland doesn’t help either, since it only runs individual X11 apps inside a Wayland session.

Modifying custom.conf

Depending on your system, you will have to navigate to /etc/gdm or /etc/gdm3. Inside this folder you will find a file named custom.conf. It will look something like:

# GDM configuration storage

[daemon]
# Uncomment the line below to force the login screen to use Xorg
#WaylandEnable=false

[security]

[xdmcp]

[chooser]

[debug]
# Uncomment the line below to turn on debugging
#Enable=true

On Debian and Ubuntu the file is /etc/gdm3/custom.conf. On Arch and Fedora it’s /etc/gdm/custom.conf.

All you have to do, is uncomment the line WaylandEnable=false. After doing so, it should look like:

# GDM configuration storage

[daemon]
# Uncomment the line below to force the login screen to use Xorg
WaylandEnable=false

[security]

[xdmcp]

[chooser]

[debug]
# Uncomment the line below to turn on debugging
#Enable=true

If the WaylandEnable line isn’t there, add it yourself under [daemon].

Restarting the gdm service

Once the modification is in place, you just have to issue the command:

service gdm restart

On systems where gdm3 is the service name, use:

sudo systemctl restart gdm3

Then log out and back in, or reboot, so the login screen starts an Xorg session. If it offers a session choice, pick GNOME on Xorg.

Done!

After restarting gdm, you will be able to access the VM’s desktop using MeshCentral.
